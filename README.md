# AI 智能农业仓储系统 · AI-Smart-Greenhouse

ESP32 + Python 端云协同的温室环境闭环控制系统。2 秒一轮的本地闭环完全离线可运行，
阿里云百炼 qwen-plus 只作为"顾问"参与参数推荐与异常诊断，不进入控制回路。

> AIoT 嵌入式系统创新大赛 · 校赛参赛作品

---

## 一、它解决什么问题

小型温室/仓储的温湿度控制长期停留在"继电器 + 固定阈值"：温度抖一下开关就跳、
传感器一个坏点就能把执行器带偏、跑一整晚却说不清控得怎么样。

本项目在同样的硬件成本上做了三件事：

1. **把"一个数字"变成"一个带置信度的估计"** —— 中位数 + MAD 剔离群，再接 EMA 平滑，
   坏点进不了控制回路；
2. **把"开关"变成"带安全闸的决策"** —— 三模式（普通/趋势/异常保护）、滞回、最小开关时间、
   执行器互斥四道闸，任何一道不过就不动作；
3. **把"跑完就忘"变成"可复现的实验"** —— 51 列 CSV 全量留痕，`report.py` 一键出七项指标与曲线。

## 二、系统架构

```
┌─────────────────────────────────────────────────────────────┐
│  云端顾问层（可选，断网不影响控制）                            │
│  阿里云百炼 qwen-plus：作物参数推荐 / 策略分析 / 异常诊断        │
│  输出必须过本地安全校验 + 人工确认，只能改"目标区间"            │
└────────────────────────▲────────────────────────────────────┘
                         │ HTTPS（点按钮才调用）
┌────────────────────────┴────────────────────────────────────┐
│  边缘智能层（PC / Python，2s 一轮）                            │
│  MAD 剔离群 → EMA 平滑 → 区间预测 → 三模式决策 → 前馈补偿       │
│  CRC8 校验 / ACK 重传退避 / 心跳三态 → CSV 全量留痕            │
└────────────────────────▲────────────────────────────────────┘
                         │ USB 串口 115200（ASCII 协议）
┌────────────────────────┴────────────────────────────────────┐
│  边缘执行层（ESP32-WROOM）                                     │
│  DHT11 采集 → OLED 显示 → 3 路 MOS 驱动                        │
│  15s 失联自保：收不到上位机数据就关闭全部执行器                  │
└─────────────────────────────────────────────────────────────┘
```

**关键设计**：实时闭环不走云端。断网、API 欠费、大模型宕机，温湿度照控。

## 三、硬件

| 器件 | 型号 / 规格 | 数量 | 连接 |
|---|---|---|---|
| 主控 | ESP32-WROOM-32 DevKit | 1 | — |
| 温湿度传感器 | DHT11 | 1 | DATA → GPIO4（需 4.7k~10kΩ 上拉） |
| 显示屏 | SSD1306 OLED 0.96" | 1 | I2C：SDA → GPIO21，SCL → GPIO22，地址 0x3C |
| 加热驱动 | MOS 模块（MOSFET） | 1 | SIG → GPIO18 |
| 风扇驱动 | MOS 模块 | 1 | SIG → GPIO14 |
| 加湿驱动 | MOS 模块 | 1 | SIG → GPIO25 |
| 超声波雾化板 | 雾化片驱动板 | 1 | 由 MOS 模块串在供电回路 |
| 上拉电阻 | 10kΩ（4.7kΩ 亦可） | 1 | DHT11 DATA ↔ 3V3 |
| 去耦电容 | 100nF | 1 | 3V3 ↔ GND |

三路 MOS 模块的信号侧必须与 ESP32 **共地**，否则永远不导通。
执行器电源（加热片/风扇/雾化）走 MOS 模块的螺丝端子，不经过主控板。

PCB 设计（嘉立创 EDA，接口板方案，DRC 0 错误）见作品介绍文档第 4 节。

## 四、快速开始

```bash
git clone https://github.com/umaima-a/ai-smart-greenhouse.git
cd ai-smart-greenhouse
pip install -r requirements.txt
```

1. **烧固件**：Arduino IDE 打开 `arduino/esp32_farm_controller_v3/esp32_farm_controller_v3.ino`，
   选开发板 `ESP32 Dev Module`，选对 COM 口，上传。
2. **连串口**：插 USB，Windows 设备管理器确认 COM 号（不要选蓝牙的 COM）。
3. **启动上位机**：双击 `run_pc.bat`（自动探测 Python 解释器），选 COM 口 → 「连接」。
4. **看数据**：曲线开始滚动、OLED 同步显示温湿度、日志出现 `DATA:T=..,H=..` 即成功。

### 启用 AI（可选）

在阿里云百炼控制台创建 API Key（`sk-` 开头），粘贴到 GUI 的 Key 输入框点保存，
或直接写进项目根目录的 `.api_key` 文件（该文件已在 `.gitignore` 中，不会被提交）。

```bash
# .api_key（不要提交）
sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

也可以设环境变量，优先级：`DASHSCOPE_API_KEY` > `QWEN_API_KEY` > `OPENAI_API_KEY`。
模型默认 `qwen-plus`，可用环境变量 `QWEN_MODEL` 覆盖。

## 七、几个刻意的取舍

**不上硬件滤波器。** 5 点滑动平均本身就是 FIR 低通，硬件 RC 再叠一层只会加大相位滞后，
对"坏点"这种大幅离群值无效。改用非线性判据（中位数 + MAD）区分"传感器抖一下"和"环境真变了"，
尖峰场景下的平滑偏移从 7.31 ℃ 降到 0.02 ℃。

**不做 PID 占空比。** 模块已实现并有自整定，但机械继电器承受不了 30 分钟内 400+ 次吸合。
默认关闭，换固态继电器（SSR）后设 `USE_V4_DUTY=1` 启用。

**不声称 MCU 上跑神经网络。** 2 秒周期、慢时变一阶热系统，统计估计 + 规则决策已足够，
且硬实时、离线可用。大模型放在云端当顾问，是成本与可靠性的权衡，不是能力不足。

## 八、环境变量开关

| 变量 | 默认 | 作用 |
|---|---|---|
| `USE_V4_PREDICT` | `1` | 启用 MAD 鲁棒估计与区间预测 |
| `USE_V4_RETRY` | `1` | 启用 ACK 重传与心跳 |
| `USE_V4_CRC8` | `0` | 启用 CRC8 校验（**开启需同步烧录固件宏**） |
| `USE_V4_DUTY` | `0` | 启用 PID 占空比（**需固态继电器**） |
